01 · Authority boundary

The model has a narrow job on purpose.

Mockingbird is not an unconstrained interviewer agent. Llama may propose one of six moves and phrase one short sentence. Python decides whether that move is grounded, affordable, focused and safe to commit.

◌ Language model

  • Proposes act, say, ok and ask.
  • Words bounded conversational follow-ups.
  • On repair turns, may return only replacement say.
  • Quotes concrete parts of completed answers.
  • Summarises already completed questions.
→

◆ Deterministic Python

  • Owns stop, skip, refusal and clarification semantics.
  • Controls focus, phase rules, caps and overflow budget.
  • Grounds quotes and computes rubric totals.
  • Commits state, provenance and candidate-visible speech.

The effective action is not necessarily the model action. The stored guard list and semantic close reason explain the transition that actually happened.

    05 · Data lineage

    Append-only effective decision, raw/final speech, repair attempt, guards, focus, budgets, telemetry, prompt and timestamp.

    06 · Quality and evolution

    Preserve the measured boundary; harden the state model.

    Keep

    • Python-owned consent, budgets and scores.
    • Grounded quotes before deterministic arithmetic.
    • Candidate-safe live projection.
    • Local provider port and reproducibility metadata.
    • Action-locked, validated speech repair before templates.
    • Explicit runner instead of a general graph framework.

    Harden

    • Immutable per-attempt and turn event records.
    • Atomic persistence, restore and crash recovery.
    • Serialized, idempotent command handling.
    • Explicit typed policy precedence.
    • Independent held-out and human-authored evaluation.

    Latest evidence. A 14-question junior probe-stress run produced 31 follow-ups: 20 byte-for-byte model questions, three safe compound-request trims, seven templates and one deterministic design-gap probe, with no generic, compound or over-cap spoken question. After correcting a copy-inducing repair prompt, a targeted replay accepted the previously failing measurement probe in 602.6 ms without changing its action. A fresh complete junior/strong pair is still required for the final aggregate repair rate.

    HighReplay cannot reconstruct every model attempt and volatile runner field

    Speech-only repairs now have structured diagnostics, but full-turn regeneration and shortening still lack complete immutable envelopes, and no restore path replays events into a runner.

    HighSnapshots are not atomic or command-serialised

    JSON is rewritten directly and commands have no sequence, idempotency key or expected state version. A future UI or voice transport would expose this mutable boundary.

    Medium-highPolicy is readable but coupled to statement order

    Runner.submit() owns control states, routing, model retries, budgets, evidence pacing and dispatch. Pin precedence pairs as tests before extracting a pure reducer.

    MediumNormal-turn provider failures have limited recovery

    Background observation fails open, but a decision or history call can still exit the CLI. Preserve a recoverable state before adding remote or voice interfaces.

    MediumDesign feedback is descriptive, but still model-mediated

    Keeping design unscored is correct. Quote presence can still be misread, so do not promote those fields without independent evaluation.

    LowFinal aggregate repair evidence is pending

    The final prompt and classifier pass the exact failing replay, but the latest full interview predates those corrections. Run a fresh paired control before claiming a final substitution rate.

    Safe extension order

    1. Freeze current precedence with adversarial control tests.
    2. Introduce utterance role, policy result, model attempt and event types.
    3. Make events authoritative; add atomic projections and restore.
    4. Serialize commands and reject duplicate submissions.
    5. Build an independent evaluation gate with multiple authors.
    6. Add generated plans only behind executable validation.
    7. Add a web UI that consumes only the live projection.
    8. Treat voice, interruption and echo control as a separate wave.
